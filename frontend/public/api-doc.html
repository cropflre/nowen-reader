2. Auth 14 endpoints

Protected endpoints accept the browser session cookie or Authorization: Bearer nwr_<key-id>_<secret>. API keys always use the owner's current role, groups, and library permissions. OPDS routes additionally accept HTTP Basic Auth with the account username and the complete API key as the password; account passwords and query-string keys are not accepted. An explicit invalid, expired, or revoked key returns 401 and never falls back to the cookie. API key management endpoints require a browser session and never accept an API key.
