# 万本书库加载优化与验证

## 反馈与定位

反馈场景是极空间 Z2S（RK3568、4 GB 内存）上的约 12,000 本 TXT 和 5,000 本 CBZ；用户已确认主要慢在 Android App。未取得该 NAS 的请求采样，不能将 16 秒全部归因于某一条查询。

确认并修复的路径：

- Android 默认请求 `seriesView=true`。原实现先加载所有书籍、标签和分类，折叠目录作品并排序之后才截取一页。
- 分组摘要逐个读取摘要、标签、分类，访问作品列表会产生 N+1 查询。
- 分组来源指纹包含 `Comic.updatedAt`，而阅读进度更新也修改该字段；读后访问列表可能触发全库分组重建。
- Android 阅读结束通知调用 `loadComics()`，会重置到第一页，丢失已加载页。首页重新创建时也会重新请求并清理筛选。
- Web 获取书库数量时，额外请求整个 `/api/series`，返回列表时超过 30 秒的缓存被删除，刷新还会禁止交互和延迟滚动恢复。

## 实现边界

逻辑书架通过共享筛选条件在 SQLite 内生成逻辑作品键、排序和分页，只加载当前页的完整书籍及批量作品摘要。标题排序保留丛书块及其内部手动、卷次、出版顺序；页数排序同样使用 SQL 分页。单成员或跨书库的过时分组关系不会隐藏原书。

SQLite 仍需扫描/聚合候选键以计算总数和排序，但分页不再将全库的完整书籍对象、描述、标签和分类加载到 Go。显式不分页的内部调用保持原有能力，并对详情加载分批处理。

`/api/libraries/accessible` 批量返回 `shelfCount`，同时保留原有 `comicCount` 的物理文件计数含义。Web 使用 `shelfCount`，不再附加请求作品列表。摘要和权限按批次/书库读取。摘要 SQL 刻意让成员索引查找先于书籍主键查找，避免 SQLite 选择按书库遍历书籍。

迁移 45 新增结构修订号及触发器，仅路径、标题、类型、归属等结构变更使分组失效。已构建修订号持久化，重启可复用；阅读、收藏、评分不会导致分组重建。构建仅确认开始前的修订号，扫描期间后续变更仍保持待刷新。历史归属检查及首次必要的分组构建在接受 HTTP 请求之前执行，升级首次启动可能因此增加初始化时间。后台扫描完成后刷新分组；请求不等待其他线程已经在执行的维护任务。

Android 保留账号/服务器/角色作用域内已加载页及筛选，阅读返回时后台刷新已加载范围，继续分页的游标保持正确。首页使用 PageStorage 保存滚动位置。过时请求、身份切换和权限拒绝均有防护；临时网络失败保留列表。Web 保留最多 20 个页面、15 分钟缓存，立即展示并后台验证，滚动恢复不等待后台验证，刷新不禁止点击。

没有更换数据库，没有新增持久化书架索引，没有修改书籍原文件。

## 本机算法基准

2026-10-24，Apple M5 / macOS arm64；每个子项运行 3 次。24 项首屏，标题升序；1.7 万本数据包含 12,000 本小说和 5,000 本漫画、1,000 个目录作品。5 万本按近似同一比例扩展。模拟书籍包含描述字段，数据库由测试创建在临时目录。

| 物理书籍数 | 原全量路径参考耗时 | SQL 分页耗时 | 原路径分配字节/次 | SQL 分配字节/次 |
| --- | ---: | ---: | ---: | ---: |
| 17,000 | 237.94 ms | 41.42 ms | 172.45 MB | 0.296 MB |
| 50,000 | 716.22 ms | 136.17 ms | 539.02 MB | 0.297 MB |

耗时为 Go benchmark 的每次操作平均值，分配字节为累计分配量，均不是 P95 或进程峰值内存。参考实现保留旧的全库加载、批量成员查找、逐个摘要及 Go 排序算法，但复用了当前底层摘要函数，因此不是旧镜像的端到端测试。数据不包括读取 CBZ/TXT 正文、封面生成、网络传输、手机渲染或冷操作系统缓存；不能将以上数字直接用于 RK3568 的体验承诺。

复现：

```sh

```

## 回归验证

- 逻辑书架：多页无重复/遗漏；标题、添加、更新、阅读时间、评分、手动顺序、文件大小、元数据、页数排序的双向结果；三种丛书内部顺序；搜索、标签、分类、收藏、阅读状态、空权限及小说独立路径。
- 权限及计数：公开/私有书库、直接/用户组管理授权、管理员、禁用书库，物理计数与逻辑计数一致。
- 分组修订：阅读进度不触发重建、路径变更触发重建、持久化构建状态复用、并发后续修订不会被错误确认。
- Android：全量 92 项测试通过；新增测试覆盖阅读返回、后台失败、权限拒绝、空筛选结果、筛选与翻页竞态、账号切换、列表缩短。
- Web：构建、类型检查/base-path/PWA 检查、阅读返回导航、书籍卡片及新增缓存/权限/请求数量测试通过。
- Go 全量测试仅 `TestNovelChapterRuleCRUDAndSystemPresets` 失败（中文章节预设未匹配 `章节 12 尾声`）。在未修改的 `7942f68` 独立源码副本中复现同一失败；本次不修改无关的章节规则。

## NAS 与手机验收

服务端对折叠书架、可访问书库和作品列表返回 `Server-Timing` 中的 `shelf`、`libraries`、`series` 阶段耗时。它们表示存储查询及返回数据准备耗时；完整 HTTP 耗时仍看请求日志。超过 500 ms 的查询额外记录 `[library-performance]` 日志，包含路径、阶段、耗时、返回数量和总数。

在相同书库、相同排序及同一手机路由下，对比升级前后：服务准备就绪后的首次进入、已访问书架返回、翻页超过两页后的阅读返回、扫描期间访问、权限变化以及冷/热封面缓存。分别记录 HTTP、服务端阶段、手机首帧和滚动恢复耗时。重点确认返回时不回到第一页，进度最终更新，滚动位置不因刷新跳动。

建议目标仍是首屏 2 秒、阅读返回 300 ms、分页服务端 P95 小于 500 ms；当前只完成本地代码及模拟数据验证，尚未在用户的 Z2S 或 Android 真机上测得这些目标，也未构建发布 APK 或部署 NAS 镜像。
