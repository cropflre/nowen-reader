# 目录分类与作品层级实施计划

状态：已实施，审查修复与相关回归验证已完成。创建及验收日期：2026 年 10 月 26 日。

需求来源：[GitHub Issue 43](https://github.com/cropflre/nowen-reader/issues/43)。代码阅读基线：`413a6a1`。执行前重新检查工作区和适用的 `AGENTS.md`，以届时代码为准核对函数与迁移编号。

目标是在一个漫画书库中正确表达“分类目录 → 作品 → 章节或卷”，避免把“韩漫”等分类目录聚合成一个巨大作品。分两期交付：第一期实现可配置作品目录深度和安全重建；第二期增加目录分类导航。性能问题独立采样，复用当前已有的大书库优化。

本文保留两阶段实现的设计与验收依据；可配置作品深度、安全重建与恢复、Web 和 Flutter 目录导航均已落地。审查发现的快照完整性校验、跨书库误拦截、目录分页、Web 书库 URL 同步及快照保留上限问题已修复，并通过 Go 全量测试、Web 构建与检查及 17 项相关 Flutter 测试。

## 产品范围与默认决策

### 数据概念

| 概念 | 含义 | 本次处理 |
| --- | --- | --- |
| Library | 书库及扫描根目录 | 增加 `seriesDepth` |
| 目录分类 | 作品目录之上的物理目录前缀 | 第二期提供独立导航，不直接写入人工 Category |
| ComicSeries | 按作品目录聚合的作品 | 保留现有实体和 API 命名 |
| Section | 作品内的季、部、篇等可识别分段 | 跟随作品深度偏移 |
| Comic | 一个可阅读文件或图片目录 | 保留身份，可能代表一话、一卷或完整单本 |
| Category | 现有人工分类 | 保持现有编辑与筛选语义 |
| ComicGroup | 现有合集或丛书 | 保持现有人工组织能力 |

### 第一期交付

1. 漫画书库可设置 `seriesDepth`，默认 `1`；`2` 对应“分类/作品/章节”。支持整数 `1` 至 `8`，方便更深目录，不做自动深度猜测。
2. 旧书库默认深度 `1`，保持已有识别行为与 ID 算法。
3. 设为 `2` 或更深时，指定深度的作品目录即使只有一个可阅读条目，也生成作品并从详情进入阅读。
4. 提供配置预览，明确作品数量变化、浅层独立条目、结构锁冲突，以及会归档的旧系列。
5. 变更配置与替换系列结构作为一次原子操作；旧人工数据有持久化归档和可执行恢复路径。
6. Flutter 现有“系列 / 单册”改为“作品 / 文件”，沿用 `seriesView` 协议；默认进入作品视图，保留用户已保存的模式偏好。
7. Web 已使用 `seriesView=true`，保留现有入口，更新相关说明、作品数与设置表单。

### 第二期交付

增加书库内的目录导航与分页作品查询，最终达到“韩漫 → 书名 A → 第 01 话”。目录名称使用“目录分类”，与人工分类筛选分别呈现。更深目录逐层导航，面包屑可返回；无目录分类的作品仍能在“全部作品”中访问。

### 范围限制

不重命名数据库中的 Comic 或 ComicSeries，不批量搬动原文件，不自动合并同名作品，不自动推断混合深度，不把目录分类转换为人工合集。本次深度只影响漫画书库，小说书库保持现有逻辑。

Flutter 目前未确认存在完整的书库管理界面。第一期使用现有 Web 管理入口配置深度，Flutter 负责消费作品与导航结果，不为本需求额外新建整套书库管理功能。

## 作品识别规则

### 深度与展示

先沿用现有路径标准化，再按 `/` 分段。设配置深度为 `d`：只有可阅读条目的标准化相对路径至少有 `d + 1` 段，才能归入指定深度的作品目录。

- `rootRelativePath = join(parts[:d], "/")`。
- 作品显示名为 `parts[d-1]`；ID 继续使用书库 ID 和完整作品相对路径。
- Section 从 `parts[d]` 开始识别，前提是它后面还有可阅读条目；保留现有季、部、篇规则和自然排序。
- 章节标签清理使用作品名及作品内相对路径，避免把分类名混入标签。
- 路径不够深时保持独立条目，禁止回退到第一层聚合。
- 图片目录沿用现有扫描边界：`韩漫/书A/第01话/` 是章节目录；`韩漫/整本图片漫画/` 是独立可阅读作品，不将其误当含章节的父目录。
- 未识别为 Section 的更深目录继续沿用现有扁平成员规则，不额外发明新的卷分类。

| 输入 | 深度 | 预期 |
| --- | --- | --- |
| `书A/01.cbz`、`书A/02.cbz` | 1 | 旧行为，一个作品，ID 与升级前一致 |
| `书A/01.cbz` | 1 | 旧行为，独立条目 |
| `韩漫/书A/01.cbz`、`韩漫/书A/02.cbz` | 2 | 一个作品，标题“书A”，根路径“韩漫/书A” |
| `韩漫/书B/01.cbz` | 2 | 一个单章节作品，标题“书B”，详情含一个条目 |
| `韩漫/书A/第一季/01.cbz` | 2 | 作品“书A”，Section“第一季” |
| `日漫/书A/01.cbz` 与 `韩漫/书A/01.cbz` | 2 | 两个不同作品，不共用 ID |
| `韩漫/散本.cbz` 或 `散本.cbz` | 2 | 独立条目，不聚合为“韩漫” |
| `区域/韩漫/书A/01.cbz` | 3 | 两层目录分类，一个作品 |

有效作品规则统一为：同书库有效漫画成员存在，且深度 `1` 至少两个成员，深度大于 `1` 至少一个成员。现有人工锁定系列的默认展示语义保持兼容，不让单成员规则意外隐藏可读内容。抽取共享条件或查询构件，避免各查询自行维护不同阈值。

多扫描根目录是前置核对项：先查清扫描器如何生成 `relativePath`、重复路径如何区分。所有深度均基于现有逻辑相对路径。若两个根下的同路径已无法区分，先记录并隔离该缺陷，禁止引入 basename ID 或假设根路径天然唯一。若会导致本次错误合并，应先补充根标识设计和测试再开放该组合。

## 身份与数据保护

### 身份规则

保持现有 `stableSeriesID(kind, libraryID, fullRelativePath)` 算法，禁止改为只使用书名。已有数据库记录的持久化 ID 优先于重新计算的候选 ID，继续保留现有按路径 upsert 的兼容性。

配置变化产生的新旧作品按以下顺序匹配：

1. 书库及完整作品路径相同，保留原 ID、元数据和人工关联。
2. 路径不同但可阅读成员 ID 集合完全相等，且新旧双方唯一对应，允许保留原 ID并更新路径。执行前排除与其他已有路径或 ID 的冲突。
3. 一拆多、多合一、部分重叠或无法证明唯一对应，生成新作品身份，旧数据进入归档。不得把分类目录的作者、简介、评分等复制给每本新书。

`1 → 2` 往往把“韩漫”拆成多部作品，不承诺这个场景的系列 ID 全部稳定。底层 Comic ID、用户阅读进度、文件收藏及阅读时长不因重分组变化。系列级收藏和合集归属单独按匹配结果处理。

### 归档与恢复

新增按书库与变更批次保存的持久化快照，例如 `LibrarySeriesRebuildSnapshot`，载荷带版本号。快照保存变更前深度、系列与成员结构、Section、人工元数据、标签、分类、系列级用户状态，以及人工合集的关联和顺序。执行时检查所有引用 ComicSeries 的表和封面资源引用，补齐遗漏。

先保存快照，再删除失效系列或替换成员，且在同一事务内提交。快照保留相关封面引用，避免自动清理使恢复记录失效；不在 API 普通响应中返回整份包含其他用户状态的载荷。

第一期必须交付管理员可用的快照列表、导出和恢复服务/API，并在文档给出实际可执行示例。无需为此制作完整管理界面。恢复遵守以下限制：

- 核对书库、载荷版本、源结构修订及变更后的作品结构，防止用旧快照覆盖后来编辑或扫描产生的新结构；不匹配时返回冲突，保留导出供人工恢复。
- 恢复旧深度和归档的系列结构及其关联，不回滚 Comic 阅读进度、底层文件或整个数据库。
- 恢复前同样保存当前系列状态；失败整体回滚。
- 深度切回原值时，优先按可验证的历史身份恢复，不静默遗弃先前人工元数据。

### 人工结构锁

区分 `metadataLocked` 与 `manualLocked`。前者保留人工元数据，后者保护系列或 Section 结构。配置预览检查受影响的人工结构锁；若变更需要拆分、合并或改写锁定结构，返回明确冲突，应用阶段保持原深度与结构。普通扫描和重复重建继续遵守既有锁保护，不能为通过唯一成员约束而删除人工关系。

## 配置流程与接口

### 创建与普通更新

现有创建、更新、列表响应增加 `seriesDepth`。创建省略时取 `1`，更新省略时保留当前值。拒绝 `0`、负数、小数、超过 `8`、null 和字符串；使用能区分省略与显式 null 的解码方式。小说书库只接受默认深度 `1`。

不改变既有未传字段客户端的行为。若执行时发现旧客户端会序列化 null，先按实际请求兼容性调整约定并同步测试和说明，不能让省略字段意外重置深度。

### 变更预览

建议增加：`POST /api/admin/libraries/:id/series-layout-preview`，请求体含目标 `seriesDepth`。

响应含当前/目标深度、旧/新作品数、单章节作品数、浅层独立条目数、保留/新建/归档作品数、结构锁冲突、有限数量的路径示例和 `sourceRevision`。只返回摘要与限定样例，避免把两万章节装入预览响应。

Web 在修改已有书库深度时自动展示预览，再使用现有保存动作应用。无需额外多轮确认。创建新书库不必先预览空库。

### 应用与一致性

现有 `PUT /api/admin/libraries/:id` 接受新深度；深度变化交给统一 service，不能先普通 `UpdateLibrary` 再异步无保护地重建。可附带预览修订号，过时返回 `409` 并要求客户端刷新预览。

在系列维护锁与数据库事务保护下读取一致数据、复核冲突、保存快照、更新配置、替换结构并提交。读者看到旧完整结构或新完整结构，不看到一半变更。普通不改变深度的设置更新不触发快照和重建。

把 `seriesDepth` 变化纳入结构修订号失效条件。沿用“仅确认构建开始前修订”的约束，不能把其他书库或并发扫描后续变更错误标为已构建。失败不得留下“新配置配旧结构”的半成品；重试不会重复创建有效作品或错误覆盖快照。

先按同步事务实现并测量两万条规模；若请求耗时超出部署超时再设计显式任务状态，不在未测量时引入另一套后台任务系统。无论采用哪种形式，配置生效和可见结构必须一致。

快照 API 建议置于 `/api/admin/libraries/:id/series-layout-snapshots` 下，提供列表、指定快照导出和指定快照恢复，均沿用管理员鉴权。

## 目录分类导航

第二期使用物理目录前缀派生目录节点，与 Category 的创建、删除、重命名完全分开。初版可通过 SQL 按前缀查询派生节点，不必增加永久分类表；只有测量证明需要时才加缓存或投影表。

建议接口：

1. `GET /api/libraries/:id/directories?parent=...&page=1&pageSize=...`：列出当前前缀的下一层分类目录、逻辑作品数和有权限的封面样例。分类只展开至作品根之前的 `d-1` 层，不把作品或章节继续当分类。
2. 复用现有 `/api/comics` 分页查询，增加 `directoryPath` 参数，并要求明确选择一个书库。`seriesView=true` 时返回该目录及后代的逻辑作品与独立条目，保留原有搜索、排序、标签、人工分类、收藏和阅读状态筛选。

根目录以空字符串表示；目录查询只接受标准化书库相对路径，拒绝绝对路径及 `..` 越界。SQL 前缀必须按路径段边界匹配，正确转义 `%`、`_` 等字符，避免“韩漫”匹配“韩漫备份”。不直接按传入参数访问服务器文件系统。

分类数量使用逻辑作品数，并复用与书架完全相同的单成员规则；当前分类下的浅层独立文件也要能访问。若当前层有分类节点又有独立作品，界面同时展示目录入口和作品区域。隐藏空分类，不暴露禁用或无权限书库的目录、数量及封面。

Web 与 Flutter 都提供“全部作品”、面包屑、目录进入/返回，并将目录路径加入分页和缓存键。切换目录重置该视图页码，阅读返回恢复原目录、已加载页、滚动位置及筛选；账号、服务器或权限变化必须隔离和失效缓存。

原人工 Category API 保持不变。OPDS 原有 feed 保持可读，第一期只同步有效作品规则；OPDS 目录分类导航可单独后续扩展，不作为第二期 UI 的前置依赖。

## 验收矩阵

| 场景 | 必须满足 |
| --- | --- |
| 升级旧库且不改配置 | 深度为 1，旧系列 ID、列表、排序和人工元数据不变 |
| 两个分类各含多本作品 | 深度 2 按书聚合，不出现以分类名命名的巨大作品 |
| 不同分类同名书 | ID 不同，元数据与进度不会串书 |
| 单章节与图片目录 | 按既定边界展示，单章节作品能进入详情与阅读 |
| 深度 3 及季、篇 | 分类逐层导航，Section 属于正确作品，章节自然排序正确 |
| 浅路径与混合深度 | 不回退折叠分类，文件仍可读；无自动猜测 |
| 一对一身份匹配 | 唯一成员集合对应时保留旧 ID 与人工关联；有歧义不猜测 |
| 一拆多及多合一 | 不传播错误元数据，旧数据有快照且可实际导出、恢复 |
| 深度来回切换 | 可验证历史身份得到保留或恢复，无静默数据丢失 |
| 人工结构锁 | 预览标冲突，应用拒绝且旧配置、成员和锁完整 |
| 数据库异常或进程中断 | 配置与结构一起提交或回滚，重启后状态可用 |
| 多次重建、并发扫描 | 不重复、不遗漏，后续结构变化仍保持待重建状态 |
| 阅读、收藏及评分 | 不触发结构重建，原 Comic 用户状态完整保留 |
| 权限与账号切换 | 节点、数量、封面和缓存不跨越权限边界 |
| 分页、搜索和人工分类筛选 | 按逻辑作品分页，计数一致，跨页无重复或遗漏 |
| 目录中含 `%`、`_`、中文或同名前缀 | 前缀查询精确按路径段匹配 |
| 旧客户端或旧服务端组合 | 未传深度走默认；客户端缺少新字段可正常解析 |
| 大书库与阅读返回 | 首屏不拉全量章节，保持目录、页码和滚动，后台刷新不清空已有内容 |
| 人工合集及 OPDS | 已有组织与下载路径继续可用，作品 ID 变更得到迁移或归档保护 |
